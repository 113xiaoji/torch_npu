# R29：DLRM 高 bag 长度与收益拐点

**在本次 CPU host-sim 中找到收益转换：新测的 L=64、128、256 均加速，且 E/EI
各档都是12/12轮更快；同轮 L=32 对照仍为负收益。** 已测点将转换区间定位在
`(32,64]`，没有测试33–63，不能据此认定某个精确阈值或任意形状都单调改善。

## 只改变输入 L

原始模型源码、forward、FP32权重、dense输入、batch128、26张表、每表1024行、
Embedding维度16、sum pooling、bottom/top MLP和sparse配置均保持R28设置。
原模型源码SHA仍为9d430a06…，权重6d0485a0…，dense输入352958c0…。
没有修改、重编或替换native候选、SDK或Python/Torch版本。

为了不把旧批次L32当作当前对照，同轮重测L32。R29从字节一致的R28L32输入开始，
保留每个bag全部32个ID，再按每表固定128x224新ID张量的前缀追加到64/128/256。
新generator seed固定为20260920，原R28 seed20260919生成的32-ID前缀完整保留。

每张表结果仍是`[128,16]`，Interaction为`[128,367]`，最终结果为`[128,1]`。

## 测量与正确性

运行于用户指定的192.168.41.204，全部新文件在
`/home/zyz/r29-multihot-high-20261110`；运行环境和二进制复用同属`/home/zyz/`的R28目录。
同boot、Python3.14.6t自然GIL=false、Torch2.13 CPU git cf30153…、NumPy2.4.4，
同native64cbe0…、SDK007及8个物理核144..158偶数、NUMA1/单LLC。
各arm同为TASK_QUEUE_ENABLE=0，Torch intra/inter-op各1线程。

- 12个cold进程先资格化，随后144个perf进程；全部串行、独立PID/进程组，起止monotonic回执无重叠。
- 每L12轮，每arm每轮50warmup/3000timed，共432,000个计时forward；L做Latin轮换，六种arm排列各两次。
- 计时仍为原`model(*inputs)`到同步返回；模型加载、外部输入准备、H2D、快照和额外数值校验排除。
  forward中原有Python索引构造仍计入。
- 每个进程额外校验26个bag、Interaction和最终结果；全部最大绝对误差0.0。
  校验在计时快照之后，释放临时张量后再同步allocator markers，不污染计时或调用计数。
- warmup/timed/stage分别核验原SDK每forward Emb26/Cat2/BMM1/Index1/Addmm6/Relu5/Sigmoid1。
  两producer各13次Embedding，EI消费流独立，MLP留caller；未用shadow代替实际调度。
- 156个进程均exit0，无timeout，进程组关闭，native owners/events退休，无SDK错误或注入故障。
- 144个计时窗口为4.561–15.551秒。共享主机，预检选定核空闲约83%–86%，背景负载有记录；
  不宣称独占，也未触碰其他工作负载。
- 本地109项测试106通过、3项原模型路径未配置而跳过；204本轮原模型CPU集成测试7项全过、无跳过。

## 为什么这次可以获益

只增加L，使每次EmbeddingBag的实际查表/求和工作增加，算子数量、输出形状及Interaction规模未增加。
协调次数没有下降，但已有并发可覆盖的工作变多，当前负载跨过了净收益点。
这与此前小L管理开销高、L32差距缩小的观察一致；没有据此声称所有算子或所有模型都适合多流。

| 每forward | off | E | EI |
| --- | ---: | ---: | ---: |
| 实际数值kernel | 42 | 42 | 42 |
| SDK队列任务 | 42 | 229 | 272 |
| SDKevent record，含allocator bookkeeping | 0 | 183 | 222 |
| SDKevent wait | 0 | 4 | 8 |

总CPU工作没有减少。进程内所有线程CPU时间/forward的跨轮中位为：

| L | off CPU时间 | E CPU时间 | EI CPU时间 |
| ---: | ---: | ---: | ---: |
| 32 | 2.384 ms | 3.121 ms | 3.233 ms |
| 64 | 2.888 ms | 3.579 ms | 3.705 ms |
| 128 | 3.871 ms | 4.555 ms | 4.652 ms |
| 256 | 5.858 ms | 6.532 ms | 6.645 ms |

因此这里是更多资源换取单次延迟下降，不能表述为CPU效率也提升。表中是全进程窗口统计，
不是各阶段互斥CPU耗时分解。EI也没有稳定地全面优于E：L128更好，L64/256略慢。

**拐点只适用于本次CPU数值host-sim。** Embedding表权重仍约1.625MiB；没有改变词表、
维度、batch，没有测试33–63或真实NPU。CANN/NPU数值、带宽饱和及设备timeline仍未认证。
