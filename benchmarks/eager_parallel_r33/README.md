# R33 real A3 phase attribution

This measures the frozen R32 package and original R31 DLRM/MetaSyn26 inputs.
It changes no model method, parameter, input dtype, operator implementation or
production package. The task-queue comparison is an explicitly separate off-only
control. Device time overlaps host time and is never added to the host partition.

`phase_probe.py` takes the existing R32 real-device config and worker helper.
It validates original CPU/NPU stages, source/binary pins, exact native routing,
closure and natural GIL=false. It supports:

- `--kind split --tap none`: original forward and final synchronization split.
- `--kind calibrate --tap active --rounds 3`: alternate disabled/enabled API
  timing windows in the same process, reversing order every other pair.
- `--kind trace --level Level0 --tap none`: separate NPU-only trace with
  unprofiled controls before/after and explicit host real-time frame timestamps.
  Warmup occurs before collection. Full CPU tracing is optional and materially
  increases latency for this workload.

Example argument suffix after the task's matched interpreter launch prefix:

```text
phase_probe.py --config R32_CONFIG --r32-worker R32_REAL_DEVICE_PY
  --arm ei --kind calibrate --tap active --warmup 50 --samples 1500
  --rounds 3 --output NEW_DIRECTORY
```

The API diagnostic requires the library generated by:

```text
python3 build_api_tap.py --include REAL_CANN_INCLUDE --output NEW_TAP_DIRECTORY
```

It uses installed SDK declarations to generate typed wrappers for descriptor,
workspace, execution, event, stream, copy and synchronization APIs. Explicit
`dlsym(handle, name)` lookups and direct CANN calls are both covered. Each wrapper
forwards original arguments/results; its caller-thread clock records exclusive
nested elapsed time, with per-caller-address counts. Other threads are excluded.
Use the ELF loader's process-local `--preload NEW_TAP_DIRECTORY/libphase_api_tap.so`
before the Python executable. This is a diagnostic tool, never part of the
normal `torch_npu` import or a global `LD_PRELOAD` setting.

The AArch64 build uses CNTVCT at its reported frequency, requiring an integral
nanosecond tick (the tested CPU reports 100 MHz). The stream-query declaration
has a version-specific private ABI fallback matching the tested PTA/CANN pair.
The reader refuses any public RTLD_NEXT task lookup: a generic dlsym wrapper
cannot preserve caller-sensitive RTLD_NEXT lookup semantics. Revalidate this
contract and all numerical gates for another runtime. A bounded caller-site
table preserves total counts/times even when cold call-site detail overflows;
overflow is reported explicitly. The measured hot event call sites were complete.

Cold positive controls establish that workspace/descriptor interception works.
Warm zeros therefore describe actual executor-cache hits for this fixed input,
not missing instrumentation. Disabled/enabled pairing measures the observer's
incremental perturbation; a separate no-preload run also remains available.
An EI outlier and its subsequent repeat windows are retained in the evidence.

`analyze.py` uses standard-library interval operations tested against analytic
examples. It separates kernel duration sum from busy union and skips the duplicate
Overlap Analysis lane. Kernel groups follow the final caller-stream Sigmoid of
each synchronized frozen DLRM forward and must contain exactly 145 kernels,
including 100 Embedding Cast kernels. The host/device epoch offset is bounded
using causal frame-start and synchronization-return constraints; no zero offset
or fitted offset is silently assumed. Tail-compute overlap is reported as bounds.

```text
python3 analyze.py --result TRACE_RESULT_JSON --trace TRACE_JSON
  --output DEVICE_ANALYSIS_JSON
```

Host elapsed accounting uses exclusive API spans. Preparation/submission is the
remaining forward time after event APIs and internal synchronization/copy/sleep.
The full final Python synchronize span is counted separately. The preparation
residual includes Python, PTA, cache lookup, allocator metadata and unwrapped
APIs; it is not an exclusive measurement of any one C++ helper. Device busy time
comes from a separately calibrated profiling cohort, whose wall latency is
not substituted for the unprofiled benchmark.

For the published summary, entire host windows are ordered by E2E mean and the
middle window is selected (the middle two are averaged for an even count).
All components come from those same windows, preserving exact additivity.
Every raw window and paired perturbation result is retained. See
`docs/R33_REAL_A3_PHASE_ANALYSIS.md` for results and PTA optimization candidates.
